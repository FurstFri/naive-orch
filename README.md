# Naive Orchestrator

Naive Orchestrator запускает и контролирует несколько клиентов `naiveproxy` на
OpenWrt. Каждый сервер становится отдельным локальным SOCKS5-портом, который можно
использовать в Podkop.

Проект добавляет LuCI-интерфейс, подписки, автоматическое обновление узлов,
healthcheck, измерение задержки и необязательный UDP over TCP. Маршрутизацию,
списки доменов и DNS по-прежнему настраивает Podkop.

## Быстрый старт

Установите на роутере с поддержкой UDP:

```sh
wget -qO- https://raw.githubusercontent.com/FurstFri/naive-orch/main/install-online.sh | sh -s -- --uot
```

Если на серверах пула уже настроен UoT-приёмник (см. [«UDP over TCP»](#udp-over-tcp)),
UDP заработает сразу после первой синхронизации подписки — ничего на серверах
разворачивать заново не нужно.

## Чем отличается от обычного naiveproxy

Для обычного TCP используется официальный клиент `naiveproxy` без изменений.
Для UDP over TCP одного `naiveproxy` недостаточно: нужна UoT-доработка из этого
проекта — sing-box-обёртка на роутере и UoT-приёмник на каждом сервере.

| Обычный naiveproxy | Naive Orchestrator |
|---|---|
| Один процесс запускается вручную со своим JSON-конфигом | procd запускает отдельный процесс для каждого узла |
| SOCKS-порты и конфиги создаются вручную | Узлы импортируются из подписки и получают стабильные порты |
| Нет LuCI и общего состояния узлов | Есть управление сервисом, статусы, ошибки и latency в LuCI |
| Нет встроенного обновления подписок | Есть ручное и автоматическое обновление с прогрессом и результатом |
| Передаёт только TCP | Опциональная sing-box-обёртка передаёт UDP как sing-box UoT v2 через TCP-туннель naive |
| Не управляет маршрутами и DNS | Также не управляет ими: это остаётся задачей Podkop |

Это не патч бинарника `naiveproxy`: сам naive по-прежнему передаёт только TCP.
Патч меняет связку вокруг него. Sing-box принимает локальный SOCKS-трафик, TCP
отправляет напрямую в naive, а UDP упаковывает в sing-box UoT v2. Затем
UoT-поток проходит через тот же TCP-туннель naive и разворачивается серверным
socks-приёмником обратно в UDP. Ключей и шифрования поверх не нужно: всё уже
идёт внутри TLS-туннеля naive, а приёмник закрыт firewall'ом от внешнего мира.

## Установка

### UDP over TCP

Если нужен UoT, выполните на OpenWrt:

```sh
wget -qO- https://raw.githubusercontent.com/FurstFri/naive-orch/main/install-online.sh | sh -s -- --uot
```

Этот режим устанавливает официальный `naiveproxy`, `sing-box` и LuCI-приложение
и включает UDP over TCP. Никаких ключей: роутер ходит на socks-приёмник сервера
через тот же naive-туннель.

Naive Orchestrator — это только роутерная часть. Чтобы UDP реально заработал,
на стороне сервера нужен UoT-совместимый приёмник (socks-инбаунд sing-box) —
это отдельный от этого проекта компонент. Если приёмника на сервере нет, TCP
через него продолжит работать, а UDP — нет.

### Только TCP

Если UDP не нужен, выполните на OpenWrt:

```sh
wget -qO- https://raw.githubusercontent.com/FurstFri/naive-orch/main/install-online.sh | sh
```

Установщик:

- устанавливает необходимые системные пакеты;
- загружает официальный OpenWrt-билд naiveproxy для архитектуры роутера;
- в режиме `--uot` устанавливает подходящий OpenWrt-билд `sing-box`;
- проверяет SHA-256 загружаемых файлов;
- сохраняет существующий `/etc/config/naive-orch` при обновлении;
- устанавливает LuCI-приложение, включает и запускает сервис.

Для обновления запустите ту же команду ещё раз. Существующие настройки сохраняются.

## Первая настройка

1. Откройте **Services → Naive Orchestrator → Settings**.
2. Добавьте подписку, укажите URL и первый SOCKS-порт.
3. Нажмите **Save & Apply**.
4. На вкладке **Status** нажмите **Обновить все подписки**.
5. Добавьте показанные upstream-серверы в direct-маршруты и direct-DNS Podkop.

После обновления каждый узел будет доступен на своём адресе, например
`127.0.0.1:1100`, `127.0.0.1:1101` и далее.

Ручной узел можно добавить без подписки. Формат адреса:

```text
https://user:password@server.example:443
```

## Статусы и обновления

- узлы проверяются параллельно через локальные SOCKS-порты;
- latency измеряется полным временем HTTP-запроса через прокси;
- вкладка Status обновляется каждые 3 секунды;
- обновление подписок выполняется в фоне;
- одновременно может выполняться только одно обновление;
- интерфейс показывает этап, текущую подписку, прогресс, число узлов и ошибку.

Статус из консоли:

```sh
/etc/init.d/naive-orch check
/usr/libexec/naive-orch/sub-update --status
```

## UDP over TCP

Официальный `naiveproxy` не поддерживает UDP и SOCKS5 `UDP ASSOCIATE`. Поэтому
включить UDP одной настройкой naive нельзя: требуется UoT-патч, реализованный в
Naive Orchestrator.

```text
TCP → naive → сервер → интернет
UDP → sing-box UoT → naive → серверный sing-box → интернет
```

Для его работы необходимы:

- `sing-box` на OpenWrt (ставится этим проектом);
- UoT-совместимый приёмник на каждом внешнем сервере (отдельный от этого проекта
  компонент, не часть Naive Orchestrator).

Ключей нет: обёртка роутера ходит socks-аутбаундом с UoT v2, приёмник — обычный
socks-инбаунд, который разворачивает UoT автоматически.

Если хотя бы на одном сервере из пула нет UoT-приёмника, TCP через него продолжит
работать, а UDP — нет.

Режим устанавливается командой с `--uot`, параметры — в **Settings → UDP over TCP**.

## Безопасность

- SOCKS-порты по умолчанию слушают только `127.0.0.1`;
- установщик роутера не изменяет firewall, nftables, DNS и правила маршрутизации;
- безопасность UoT-приёмника на сервере (firewall, доступность только по
  hairpin через аутентифицированный naive) — забота серверного компонента,
  который не входит в этот проект;
- рабочие JSON-конфиги хранятся в tmpfs с правами `0600`;
- пароли прокси не выводятся в LuCI целиком.
